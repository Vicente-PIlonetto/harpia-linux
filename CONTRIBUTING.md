# Contribuindo

O projeto está em formação: alterações devem preservar rastreabilidade e não declarar recursos como implementados sem evidência reproduzível.

1. Descreva objetivo, escopo e impacto nos perfis Base, Server e Desktop.
2. Não envie credenciais, chaves privadas, IPs pessoais, UUIDs de disco ou logs sem revisão.
3. Declare origem, versão, hash e licença de fontes de terceiros.
4. Não habilite serviços com configuração incompleta; instalação e ativação são decisões diferentes.
5. Para mudanças em build, registre comandos, ambiente, entradas fixadas e resultado.

Pull requests não confiáveis não devem executar código no runner Proxmox sem isolamento e aprovação. Não há SLA de revisão durante a fase experimental.

## Licenças

Nenhuma licença foi escolhida para o código original. Preserve avisos e termos de terceiros; não adicione conteúdo de terceiros sem atribuição e permissão compatíveis.
